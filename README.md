# Life Dashboard

A personal productivity dashboard built with Python/Flask and TinyDB. Runs locally for development and deploys to GCP Cloud Run for access across devices, protected by Identity-Aware Proxy (IAP).

---

## Features

- **This Week** — AI-generated background image + 7-day card strip (today → +6) showing events and tasks per day
- **Tasks** — Work and Personal task lists with priorities, due dates, and checkbox completion
- **Projects & Year Ahead** — Progress tracking per project, a colour-coded 2-year roadmap, and focus-distribution charts
- **Full CRUD** — Add, edit, and delete every item via modal dialogs; all changes persist immediately
- **Dual storage** — Local `dashboard.json` for development; GCS bucket in production
- **Dutch public holidays** — One-click sync from the Nager.Date API
- **Recurring events** — Birthdays and other yearly recurring events computed client-side
- **Google Calendar sync** — One-click sync from Google Calendar via service account (no OAuth flow)
- **Mac Calendar sync** — Import upcoming events from the Mac Calendar app via a local script (iCloud calendars etc.)
- **AI background** — Daily photorealistic scene generated by Gemini 2.5 Flash, reflecting the week's events and Amsterdam weather
- **MCP server** — Exposes dashboard CRUD as tools so Claude and other AI agents can read and write data

## Running Locally

```bash
# 1. Activate the virtual environment
source venv/bin/activate

# 2. Start the server
python run.py

# 3. Open your browser
#    http://127.0.0.1:5000
```

Local mode uses `data/dashboard.json` on disk. No GCS credentials or API key needed.

## Deploying to GCP

> **Not currently deployed.** The GCP project behind this app was deleted on 2026-08-16, and
> the GitHub Actions deploy and teardown workflows have been removed. This document is kept as
> a reference for provisioning from scratch; it has not been exercised since the teardown.

See **[docs/DEPLOY.md](docs/DEPLOY.md)** for full instructions. In summary:

1. Set up the OAuth consent screen in the GCP Console (one-time manual step)
2. Copy `.env.example` to `.env` and fill in your values
3. Run `./deploy/setup.sh` — provisions Cloud Run, GCS, Load Balancer, IAP, Workload Identity Federation, and the background generator Cloud Function
4. Add the printed variables to your GitHub repo (Settings → Actions → Variables)
5. Point DNS to the Load Balancer IP and wait ~15 min for SSL to provision
6. Restore a deploy workflow (the removed `.github/workflows/deploy.yml` is in git history) and run it

Once live, the dashboard is available at your domain, gated by your Google login via IAP.

## REST API

All routes require either an IAP browser session or `X-Api-Key` header.

| Method   | Path                      | Description                      |
|----------|---------------------------|----------------------------------|
| `GET`    | `/api/<table>`            | List all documents               |
| `POST`   | `/api/<table>`            | Create a document                |
| `PUT`    | `/api/<table>/<id>`       | Update a document                |
| `DELETE` | `/api/<table>/<id>`       | Delete a document                |
| `POST`   | `/api/holidays/sync`      | Sync NL public holidays          |
| `POST`   | `/api/gcal/sync`          | Sync Google Calendar events      |
| `POST`   | `/mcp`                    | MCP JSON-RPC endpoint (AI agents)|

Valid tables: `tasks`, `events`, `projects`, `year_events`, `holidays`, `recurring`, `gcal_events`

## Google Calendar Sync

Click the **📅 GCal** button in the Upcoming Events panel to sync. The dashboard fetches the next 60 days of events from Google Calendar using the Cloud Run service account identity — no OAuth flow needed.

**One-time setup:**

1. Enable the Calendar API on your GCP project
2. Share your Google Calendar with the Cloud Run service account email (Viewer)

Synced events appear read-only (no edit/delete). Configurable via `GCAL_CALENDAR_ID` and `GCAL_SYNC_DAYS` env vars.

## Mac Calendar Sync

For iCloud-only or other non-Google calendars, `scripts/sync_calendar.py` imports events from the Mac Calendar SQLite database and pushes them to `/api/events`.

```bash
python scripts/sync_calendar.py sync --dry-run  # preview
python scripts/sync_calendar.py sync            # import (default 30 days)
python scripts/sync_calendar.py sync --days 90  # custom window
python scripts/sync_calendar.py calendars       # list available calendars
```

See **[docs/MAC_CALENDAR_SYNC.md](docs/MAC_CALENDAR_SYNC.md)** for full details.

## Customising

- **Add categories** — extend the `<select name="cat">` options in `app.js` `MODAL_CONFIGS`
- **Change colours** — edit CSS variables in `style.css` `:root`
- **Add a new tab** — add a `<button>` in the nav and a `<section id="tab-*">` in `index.html`, then add a render function in `app.js`
